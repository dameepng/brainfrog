## 2. Epistemological and Authorization Architecture

In strict adherence to BrainFrog security guidelines, this audit distinguishes four operational categories:

```
[ Model Output (Untrusted) ]
          │
          ▼
[ Code-Enforced Schema & Normalization Gate ]
          │
          ▼
[ Human Approval & Cryptographic Contract Binding ]
          │
          ▼
[ Runtime Pre-Mutation Enforcement Gate (Grants Mutation Rights) ]
```

1. **Information Inferred from Model Output**: Natural-language PRD proposals, strategy labels, proposed steps, and constraints generated by System 2 models. This information is **strictly advisory and untrusted**. A model asserting that an operation is safe, idempotent, or backwards-compatible provides zero authorization authority.
2. **Data Validated by Code**: Structured normalization and schema invariant enforcement performed deterministically by `PlanRegistry`, `compute_metadata_semantic_digest`, and `has_unresolved_blocking_unknowns`. Code verifies types, structures, and detects malformed or tampered inputs.
3. **State Bound to Approval**: The cryptographic fingerprint (`plan_content_hash`, `plan_metadata_hash`, `plan_revision`, `session_id`, `approved_targets`) captured in `ApprovedExecutionContract` when a human approver explicitly reviews and authorizes a proposed operation.
4. **Mutation Rights Granted by the Runtime**: The runtime execution rights enforced immediately before mutating disk state in `StructuredStepRunner.revalidate_pre_mutation()`. Mutation rights are granted solely by an unexpired, matching, untampered execution contract.

## 3. Initial Findings: Confirmed Vulnerabilities vs. Theoretical Risks

| Threat Vector | Theoretical Risk | Confirmed Vulnerability | Severity | Remediation |
| :--- | :--- | :--- | :--- | :--- |
| **Unknown-State Collapsing** | Models omit `blocking_unknowns` or output non-blocking questions; runtime either permits unreviewed work or blanket-blocks everything. | **CONFIRMED DEFECT 1**: Orchestrator's fallback treated explicit empty list `raw_blocking = []` identically to omitted field (`raw_blocking = None`), causing non-blocking clarifying questions to be converted into global blocking unknowns, halting authorized independent work. | **HIGH (Availability / Correctness)** | Differentiated `raw_blocking is not None` (explicit assessment) from `raw_blocking is None` (omitted field / legacy schema). Explicit empty lists preserve questions without promotion. |
| **Malformed Blocking Unknown Leak** | Malformed items in `blocking_unknowns` (e.g., scalar `12345`, boolean `True`, empty dict `{}`) cause unhandled runtime exceptions or bypass. | **CONFIRMED DEFECT 2**: In `PlanDocument.get_unresolved_blocking_unknowns()`, unrecognized item types were discarded (`else: continue`), allowing malformed unknown items to silently disappear and grant untrusted execution. | **HIGH (Security Bypass)** | Converted all unrecognized/malformed unknown items into unresolved global blocking decisions (`decision = "Malformed blocking unknown item #..."`), ensuring fail-closed blockage. Flagged `metadata_malformed=True`. |
| **Lifecycle State Tamper Alert False Positive** | Hash verification detects ordinary status updates (`READY` -> `IN_PROGRESS`) as out-of-band tampering. | **CONFIRMED DEFECT 3**: `compute_metadata_semantic_digest()` erroneously included `status` and `revision` in its authoritative dictionary. When `update_status()` advanced `READY` (rev 1) to `IN_PROGRESS` (rev 2), `metadata_hash` changed on disk, causing contract validation to fail with a false tampering alert. | **HIGH (Lifecycle Denial of Service)** | Excluded ephemeral lifecycle bookkeeping (`status`, `revision`) from the semantic metadata digest. Semantic digest now strictly covers the authoritative plan specification consumed by BUILD. Revision/status validity are independently enforced by the contract. |
| **Legacy Contract Bypass on Architecture Plan** | An older execution contract without `plan_metadata_hash` executes a newer architecture-aware plan without re-review. | **CONFIRMED GAP 4**: Older contracts lacking `plan_metadata_hash` were permitted to execute plans that had architecture constraints, skipping metadata integrity validation. | **HIGH (Integrity Bypass)** | Enforced in `validate_plan_binding()` and `revalidate_pre_mutation()`: any plan with architecture metadata or metadata hash requires `contract.plan_metadata_hash`. Legacy contracts fail closed requiring review and fresh reapproval. |
| **Approval Flow Parameter Omission** | Runtime approval service does not capture metadata hash during request creation. | **CONFIRMED DEFECT 5**: `ApprovalService.create_request()` lacked `plan_metadata_hash` in its signature and did not resolve it from the plan registry, resulting in runtime-generated contracts lacking metadata bindings. | **MEDIUM (Integration Gap)** | Added `plan_metadata_hash` parameter and automatic resolution from `PlanRegistry(ws_resolved).get_plan(plan_id).metadata_hash`. |

## 4. Unknown-State Semantics Before and After Remediation

The runtime now strictly distinguishes five distinct unknown states:

| Unknown State | Meaning | Before Fix Behavior | After Fix Behavior |
| :--- | :--- | :--- | :--- |
| **1. Missing Field (`raw_blocking is None`)** | Provider omitted `blocking_unknowns` or legacy schema was used. | Promoted clarifying questions if present, but did not consistently flag provenance. | **Fail-Closed Promotion**: If clarifying questions exist, they are normalized into unresolved blocking unknowns. If both fields omitted, plan loads as draft requiring human review prior to readiness. |
| **2. Explicit Empty List (`raw_blocking == []`)** | Provider explicitly evaluated codebase and established no blocking decisions. | **BROKEN**: Treated `[]` as falsy, triggering fallback that promoted non-blocking questions into global blockers. | **Preserved Intent**: `blocking_unknowns = []`. Clarifying questions remain preserved as non-blocking inquiries. Independent authorized steps execute cleanly. |
| **3. Nonempty Valid List (`raw_blocking = [{...}]`)** | Provider identified specific architectural blocking decisions. | Captured unknowns; step runner halted if step ID or files matched. | **Strict Pre-Mutation Gate**: Halts affected steps before mutation. Unrelated independent steps proceed. Steps assuming answers in prompt text remain strictly halted. |
| **4. Malformed Field (scalar, bool, invalid dict)** | Provider returned invalid shape or corrupt JSON. | **LEAK**: Non-dictionary/string entries in list were skipped via `continue`, silently clearing unknown gate. | **Fail-Closed Conversion**: Malformed entries become unresolved blocking unknowns and `metadata_malformed=True` is flagged. Contracts fail closed. |
| **5. Context 'unknown' (`target_context: "unknown"`)** | Architectural domain is broad or unclassified, but no blocking decision identified. | Theoretical risk of blanket execution halting. | **Bounded Execution**: Target context alone does not block steps. Steps execute within approved file boundaries unless a concrete blocking unknown applies. |

## 8. Remaining Limitations & Boundaries

1. **Autonomous Clarification Resolution Out of Scope**: Phase 3C deliberately avoids creating interactive or automated question-resolution workflows (e.g., interactive CLI wizard or LLM-driven question answering). Unresolved blocking unknowns halt execution and require human decision-making. Phase 4 will introduce interactive clarification workflows.
2. **Deterministic Synthetics Only**: Live provider API calls were not used in place of deterministic, repeatable contract tests. Mocked provider payloads accurately reflect real provider output formats.
3. **No Automatic In-Place Schema Migrations**: Legacy plans on disk are not automatically updated or rewritten when loaded. They remain read-only until a human user or authorized transition explicitly modifies them.
